# Ru - OCR AOW v0.3

Небольшой Windows-переводчик для Age of Wushu / 九阴真经.

## Возможности

- F8 — выделить область и перевести на русский.
- F9 — включить/выключить перевод при наведении мыши.
- F10 — выделить область и скопировать её как изображение в буфер обмена.
- Вкладка «Перевод» — вставить текст и перевести прямо внутри программы через DeepSeek.
- OCR: китайский (упрощённый/традиционный), тайский, вьетнамский, английский, авто.
- Игровой словарь терминов.
- Небольшой интерфейс в стилистике вложенных игровых материалов.
- Системный трей.
- Автор и ссылка на автора.
- Офлайн-активация по коду устройства.

## DeepSeek

В `Настройки` вставьте API key DeepSeek. По умолчанию используется `deepseek-v4-flash`.
Ключ хранится локально в `user_data/settings.json` рядом с portable-программой.

## Активация

При первом запуске программа показывает код вида `AOW-XXXX-XXXX-XXXX`.
Автор запускает отдельный файл `Generate-License.ps1` из набора AUTHOR LICENSE TOOL,
вводит код устройства и получает персональный код активации. Пользователь вставляет его в приложение.

Важно: набор AUTHOR LICENSE TOOL содержит приватный RSA-ключ. Никогда не загружайте его в публичный GitHub и не передавайте пользователям.

Это офлайн-защита от простого копирования. Как и любая клиентская защита, она может быть обойдена при серьёзном reverse engineering. Для коротких одноразовых кодов, отзывов лицензий и лимита устройств позже лучше подключить сервер лицензирования.

## Сборка без Python на компьютере пользователя

Загрузите содержимое этого проекта в отдельный GitHub-репозиторий. Workflow уже лежит в `.github/workflows/build-windows-portable.yml`.
Откройте `Actions -> Build Ru-OCR-AOW Windows Portable -> Run workflow`.
После завершения скачайте artifact `Ru-OCR-AOW-Windows-Portable`.

Python нужен только серверу GitHub при сборке, конечному пользователю — нет.

## Замечание по режиму наведения

OCR выполняется локально, а запрос к DeepSeek отправляется только когда распознанный текст изменился. Это снижает количество API-запросов. Для наведения лучше выбирать язык вручную, а не `Авто`.


## v0.4 — исправление запуска OCR в portable-сборке

Исправлена ошибка `A dependency error occurred during pipeline creation` в PyInstaller-сборке.
Причина: PaddleX проверяет OCR-зависимости через `importlib.metadata`, а их metadata могла не попасть в portable-папку.
Теперь сборка явно устанавливает `paddlex[ocr]`, включает metadata OCR-зависимостей и после сборки запускает автоматический self-test готового EXE.


## v0.7.0 — несколько переводчиков и автоматический резерв

В настройках доступны Azure Translator, DeepL, Gemini и DeepSeek.
Режим по умолчанию: **Авто: Azure → DeepL → Gemini → DeepSeek**.
Если у текущего сервиса закончилась квота, возникла ошибка API или сеть не дала ответ, программа автоматически пробует следующий настроенный сервис.

Для работы достаточно настроить хотя бы один API key. Ключи не вшиваются в исходный код — они сохраняются в пользовательских настройках приложения.

При наведении F9 ошибка отдельного переводчика больше не должна создавать ложное впечатление, что не работает OCR: если есть резервный сервис, будет использован он; если отказали все, причина появится в строке состояния.
